# Launch ownership and selected experiment claims

Future native runs record `launch-journal.json` before display or participant launch. Each planned role moves from `not-attempted` through a persisted `spawning` intent to a PID/start/boot snapshot or an explicit `spawn-failed` result. The process list preserves those snapshots rather than resampling already exited processes. A failed attempt may have a never-attempted suffix; a successful attempt cannot. Missing identities, unresolved spawn intents, altered ordering, duplicated identities, and changed run/runtime/owner bindings fail closed.

The outer owned-process subreaper writes `supervisor-cleanup.json` only after its original controller and all adopted children are gone. This receipt binds the original run, runtime, controller, supervisor and exact journal/process-list bytes. Collection, export and failed-slot registration validate the receipt and require all recorded owners dead. New runs cannot bypass the journal by dropping its mutable marker: the retained tool-source inventory identifies the protocol too. Legacy full-ownership evidence remains valid under its prior cardinality contract. Historical partial failures without a journal are not retroactively repaired.

Experiment registration now binds `claim_protocol: 1` and its canonical absolute `experiment_root`. A measured runtime must include that path as `measurement_experiment_root` before run creation, alongside `measurement_context` and measurement inputs. At run entry, an exclusive `{phase}-{slot}-claim.json` binds the intent digest, run directory, run ID, run hash and runtime hash before any display or participant starts. Experiment writes fsync both file and directory. The same still-created run may resume before native execution; a different run cannot reuse the intent, even if the original failure cannot be collected or recorded. Running and failed runs cannot restart. Copying the experiment directory does not create a new claim namespace for its old registration.

Report assembly requires the exact claim. Recording, freezing calibration and evaluating measured results reproduce the report from the claimed raw run and compare the complete result, preventing changed metric values from being accepted merely because input labels match. A selected failed attempt records no metrics, remains terminal, and retains its ownership evidence and claim digest. There is no cleanup waiver or replacement slot.

Controls include synthetic invalid/missing/foreign/duplicate/live ownership, in-flight spawn loss, partial failure export/registration, cloned experiment root, repeated intent acquisition, changed metrics, existing full-ownership compatibility, and actual tiny-process wrapper startup/Popen failure and cleanup. These controls are harness tests, not Minecraft, visual acceptance, or performance measurements. Existing native evidence remains bound to its recorded artifacts and retained tools; future runs need freshly frozen tool identities after integration.
