# Native server store smoke

This gate runs the actual packaged Fabric, Paper or NeoForge server with a real Fabric client and an explicit test-only LSSApi consumer. Two fresh client processes join sequentially. The first must receive the independently specified block column from native disk (source1); a read-only SQLite witness then proves a committed v20 row whose independently decompressed bytes match that delivery. After actual disconnect and session retirement, a new client root must receive the identical column from the server store (source3). Both sessions require real client and server v20 observations, exact payload-object association with the active decoded callback, and the independent decoded block oracle. No mock transport, direct store deposit or gametest substitution satisfies this gate.

Build `test-fixtures/server-smoke-client` using the line's JDK and actual Minecraft version, with `-PlssFabricJar=<candidate>` and `-PlssCommonJar=<common>`. The1.x lines use `remapJar`;26.x uses `jar`. Capture actual native client inputs with `:fabric:captureSmokeRuntime -I tools/rig/client-runtime.init.gradle -Dlss.smoke.evidence=<fresh-output>`; this prepares dependencies and evaluates actual launcher getters without launching. The snapshot loader/classpath/assets and candidate hashes must match the selected recipe. No ordinary launcher profile or authentication material is required.

`tools/rig/assemble_platform_recipe.py --spec <explicit-inputs.json> --output <fresh-directory>` prepares one platform subrow and does not create/run it. The specification includes source path, platform, exact client/server/fixture paths plus SHA256, native capture, Java, endpoint, server dependency profile and cache. Fabric/Paper additionally need the exact bootstrap and complete immutable dependency root. A bare downloader launcher is insufficient. A Fabric manual installer closure may instead be supplied via `fabric_closure`; `prepare_fabric_bootstrap.py` verifies the exact official installer, actual server and loader artifacts, and records the resulting file manifest.

NeoForge requires `native-installed-closure` from `prepare_neo_bootstrap.py`, an exact official installer identity, native Minecraft/Neo pins, and all resulting bootstrap files. Captured development-bootstrap inputs are diagnostic preparation only and cannot satisfy these production server rows. Installer execution is an explicit preparation step in the exclusive Java slot, never part of a live smoke. `swap_native_neo_server.py` reuses that installed closure for other fixtures: it replaces only the owned server launch/dependencies/candidate/profile, requires native Neo fixture metadata, and preserves independent client profiles and explicit LSS fixture properties.

The resulting profile/runtime/scenario must pass the selected line's `rig plan`, then use that same line's owned `rig create`, `rig run` and `rig collect` wrappers. The maintained proof dispatcher recomputes raw native server/client evidence and verifies the immutable target recipe; a boolean assertion or copied old report cannot pass. Keep every failed attempt, complete process cleanup and export the exact candidate/fixture identity through the compatibility record helper only after collection.

This is a functional server gate. It proves neither client terrain rendering nor physical Netty saturation, Folia concurrency, performance budgets, or an entire optional-mod gametest suite.
