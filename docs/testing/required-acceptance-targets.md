Required rows remain unverified until an explicit acceptance_target is supplied from selected current artifact paths and owning maintained profiles. Never derive it from a passing validation record or select a pass across targets.

The target binds profile, scenario version and full scenario hash, primary candidate, every metadata-declared LSS candidate role, exact selected fixture map, and scenario_checker_sha256. The latter hashes a declared dependency closure: common proof/review/runner files; selected route/checker roots; actual maintained Python driver/wrapper paths in the runtime; and their local static imports. Whole dispatcher/runner files and the three ownership wrappers are conservatively included. Common imports, including endpoint, immutable-tree and toolchain verification, are traversed transitively. Only imports belonging to explicitly known unused scenario branches are excluded; new common helpers remain included. Unknown route/checker kinds fail until explicitly declared. Changes inside a shared dispatcher conservatively require new proof or a separately reviewed equivalence; no automatic semantic equivalence is inferred.

The exported record retains the complete runtime-tools digest for historical provenance. This full-tree digest is not an expected acceptance axis. The scoped export reads retained source files, verifies every selected hash against the original run manifest, and binds that map/hash. Adding an unrelated maintained tool cannot invalidate matching evidence; modifying a used checker/helper does, even when the scenario version is unchanged.

For an exact target, only its newest timestamp group can pass. Any non-pass in a tied newest group keeps the row unverified; filenames/run IDs cannot select a favorable pass. Older identities remain in the catalog without satisfying a new target.

The maintained tools implement these checks. Existing records lacking the new scoped identity remain retained and cannot satisfy an explicit target unless re-exported from their original retained evidence with the required dependencies present. No blanket historical approval or equivalence is generated.

The target also binds versioned initial runtime settings: generated and staged configuration, initial world inputs or the fresh-world premise, declared backend/GPU/environment, per-launch JVM flags and endpoints. Only the settings SHA256 and schema version are exported. Expected staged configuration/world bytes are checked before target construction; retained exports bind their original manifest inputs. Auth, owned display/PID/lock identities and cache placement are excluded. A settings-only change cannot reuse a previous pass. Records missing this identity remain historical until honestly re-exported from matching original evidence.
