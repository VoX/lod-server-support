### P2 / WI-2 extension: completed generation outcomes survive removal and target a replacement session

**Primary code:** `common/src/main/java/dev/vox/lss/common/processing/OffThreadProcessor.java:1536`, particularly current-state lookup and dimension-only checks at 1556–1573, removal of the current state's pending entry at 1581, and done-bit publication at 1631. The old generation outcome has no originating session identity.

**Paper producer:** `paper/src/main/java/dev/vox/lss/paper/PaperChunkGenerationService.java:313` and `:342` construct UUID/dimension-only ready records; `:351` hands completed records to the common mailbox. `removePlayer` at `:382` removes only still-active callbacks, leaving completed `mainReady` records. Once posted, even clearing `mainReady` cannot retract a record already owned by the common lossless mailbox. `PaperRequestProcessingService.java:1138` invokes this cleanup during ordinary removal; lifecycle events drain before generation collection and snapshot posting (`:1320`, `:1361`, `:1605`).

**Reachable transition:** An old player session has a legitimately admitted generation. The platform serializes its result, and a subsequent dirty edit overtakes it. The processing thread is delayed while the pump publishes the old completion, removes the player, and registers a replacement with the same UUID and dimension. Ordinary reconnect during a delayed processing cycle suffices; no mutable seed, same-tick reconnect, or Folia threading premise is required. Lossless snapshot merging retains the old completion. When processing resumes, removal sweeps the old generation tracking/dirty taint before the retained ready record drains. `processGenerationReady` resolves the replacement state and passes both dimension-string guards. The stale outcome is now treated as fresh.

**Impact:** Pre-edit generated bytes can be delivered into the replacement session, mark its done-bit, stamp freshness, and (if enabled) deposit into the store. A warm replacement's subsequent request can therefore terminate with false up-to-date. Old permanent-failure ready records share the ownership hole and can produce NOT_GENERATED against the new state, although the supplied probe focuses on the success/dirty-taint arm. This is the same user-visible failure family as report02's old disk-read completion, but a disk result-sink fix alone does not close it.

**Why current defenses do not close this:** `PaperChunkGenerationService.java:306` correctly rejects an active load callback whose token no longer matches the active launch. That check has already succeeded before the outcome enters `mainReady` / the common mailbox. The common state's registered-dimension guard blocks A→B dimension changes, but same-dimension reconnect passes. Pending-null alone is intentionally not an ownership oracle: same-session late/ghost completions are supported.

**Evidence/probe:** `/home/vox/.local/state/lss-review/20260906-astra/probes/server/dev/vox/lss/common/processing/GenerationSessionOwnershipReviewTest.java`, method `bufferedGenerationMustNotLoseDirtyTaintAndSealReplacementSession`. It uses the real processor and mailbox, real disk-first admission, an authoritative not-found result to produce a real generation ticket, the real dirty-taint ingress, and a `beforeRouteHook` barrier to model a delayed processor while platform pump publications continue. It then posts an old ready outcome, performs service-order removal/re-registration, and publishes a replacement snapshot. Expected regression assertions: no delivery to the fresh state and no fresh done-bit. Parent owns execution; no local run was attempted.

**Existing test gap:** `OffThreadProcessorDiskResultTest.generationTrackingIsSweptWhenAPlayerLeavesMidGeneration` explicitly assumes the old outcome never drains and tests a newly admitted outcome after removal. `PaperChunkGenerationServiceTest.removePlayerPrunesActiveAndLateCallbackIsNoOp` covers callbacks still in the active map. Its timeout/resubmit token tests cover superseded launches. None covers a completed ready record retained across a session replacement in the shared mailbox.

**Fix plan:** Expand WI-2's origin ownership through generation admission/tickets, per-player callback attachments, and ready records; validate that ownership before consuming current tracking or removing a current pending entry, marking done, emitting terminal responses, or depositing data. Keep the load-level token for timeout/resubmit protection and preserve same-session ghost handling. Add the external regression to the common test suite and an adapter-level Paper test for completion→remove→`tick()` showing ready ownership survives the adapter boundary; include permanent-failure and shared-load/two-player arms. Clearing Paper's ready list by UUID is useful hygiene but insufficient as the correctness fix.
