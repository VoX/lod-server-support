## Accepted amendment: WI8 stationary rename completeness

**P3 / pre-existing behavior within the planned regression matrix, not a newly introduced or stock-server gameplay defect.** `common/.../farplayers/FarPlayerClientTracker.java:87` updates `nameByUuid` on an incremental same-index/same-UUID rename, but an existing immutable `TrackedFarPlayer` retains its previous `name` until `onUpdates` rebuilds it around lines124–129. Concrete sequence: full roster binds UUID A/index0/nameOld; update makes A drawable; incremental roster renames that same binding to nameNew; no motion/state update follows. `snapshot().get(A).name()` remains nameOld indefinitely under intentional stationary delta suppression.

The WI8 plan explicitly includes same-binding rename while preserving motion, and the new identity fixture did not assert this sequence. Proposed completion: when accepting a rename for a currently tracked UUID, replace its immutable tracked row's name while retaining entry/cadence/time/motion/equipment; add a decoded-roster regression with no following update that verifies new name and the same motion/equipment state. Do not fix this with expiry or reset motion. Parent accepted this amendment and is implementing it; this report does not claim to validate that later change.

## No blocking implementation defect found in the other reviewed packages

- **WI6:** server-owned `applyMode` runs ahead of ordinary broadcast cadence in both platform wrappers and avoids snapshot construction while OFF. Published-roster tracking prevents an initial-OFF session from spuriously emitting a withdrawal; accepted clears advance epoch and mutate state only after send success. Declined clears retry while OFF. OFF→ON supersedes a pending clear, forces a fresh full roster, and clears rows so stationary targets receive first state again. The server-control bypass is distinct from ordinary client preference throttling. Subscription/privacy retention is preserved. Existing decoded-wire tests exercise the ordinary cycle, withheld clear, retry, rapid OFF/ON and initial-OFF control. The common broadcaster has a single-thread ownership contract; arbitrary concurrent applyMode calls are not a valid finding.
- **WI8 identity cleanup:** occupied-index displacement removes the former identity's binding/name/drawable row. Moving a UUID removes its former index first, so later removal of that obsolete index cannot delete its current binding. Forward/reverse/name/tracked maps have the cap/reset lifecycle. The renamed immutable row issue above is the sole concrete completeness gap found here.
- **WI9:** both immediate-mode 1.21.1 seated dispatcher catches restore the pass pose before latching/continuing.
