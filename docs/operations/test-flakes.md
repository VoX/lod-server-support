# Known test flakes and environmental failures

**This file is the canonical home for known CI test flakes and environment-specific test failures — keep it up to date, and record all similar findings here.** When a test failure is diagnosed as a flake or an environment quirk (not a code regression), add an entry here so the next contributor/session **re-runs rather than chases a phantom regression**. Each entry gives the test, the symptom, why it's benign, and the action. (These are also mirrored in the assistant's project memory, but this file is the in-repo source of truth.)

Since 2026-07 `build.yml` contains the flakes automatically: docs-only changes (`**.md`, `docs/**`) skip the workflow entirely, the Tier 2 and Tier 3 gametest steps **retry once** on failure (each retry emits a `::warning::` annotation in the run summary — a retried-then-green run means a flake fired, not that nothing happened), and the first attempt's logs/crash-reports are uploaded as `gametest-flake-evidence-*` artifacts (failures upload `gametest-failure-evidence-*`, retention 30 days — GitHub's raw job logs for this repo expire within days, the artifacts are the durable record). A job that is red even after its retry is very unlikely to be one of the entries below — diagnose it from the artifacts before re-running.

## WSL physical host exhaustion and interrupted staging (2026-09-10)

Two local WSL interruptions occurred during project-improvements work; the user identified a full underlying Windows drive and freed space after the second interruption. The physical volume hosting the Ubuntu VHDX had a different capacity budget from Linux's virtual filesystem. Interrupted create `20260910T151242Z-55d5182e7c2b` retained 134 zero-byte files, no manifest/runtime/owner/journal/supervisor record, and no native launch. Other recent writes were missing or empty after recovery. This is failed preparation and evidence damage, never an accepted test or a reason to waive a checker.

Preserve the original incomplete run and failed attempts. Establish actual VHD host capacity, then verify recorded hashes for staged inputs, product artifacts, world snapshots and retained evidence before preparing a fresh run. Do not resume a measured slot with a different run, invent missing ownership receipts, or reuse prior-boot GPU proof for new measurement binding. Restore only from verified retained bytes; label reconstructed attribution separately from recovered originals. Recovery checks are bounded work outside active measurements, not periodic full-tree scans.

The [storage guard](../implementation/physical-host-storage-guard.md) now requires a 50 GiB reserve on Linux and the actual host volume, plus conservative staging/growth admission. It monitors capacity cheaply during readiness and observation, and propagates low-water or monitor errors through owned cleanup.
