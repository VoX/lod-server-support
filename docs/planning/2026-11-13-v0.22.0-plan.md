# 0.22.0 plan

Status: reviewed 2026-11-13 (two reviewers; fold in §8), in implementation. Ships as
`0.22.0-beta.1` on 26.3 and 1.21.1 first ([decision 0002](../decisions/0002-beta-first-releases.md)),
then `0.22.0` on 26.3, 1.21.1, 26.2 and 1.21.11. 26.1 and 1.21.10 are frozen.

Source: the post-0.21.0 review. Only 7 of 43 issues were bugs in the mod; 16 came from the mod
doing nothing without saying why, from another mod, or from confusion between the two builds.

Review cut the scope: settings tolerance (old §B) moves to 0.23.0 with its own plan, because as
first written it could turn a privacy feature on; the generation cap (old §F) is dropped. The
command names (§3) moved to 0.23.0 during the build. §9 lists what building it changed.

## 1. Say why nothing is happening (client)

**Before.** After the handshake ladder ran out the client stayed in `AWAITING_NEGOTIATION` forever
with DEBUG logs only. A protocol mismatch was a WARN in the log. A server that answers "disabled"
(off for everyone, off in this world, or permission missing) looked the same to the client. With no
Voxy and no map mod, nothing could be shown and nothing said so. Nothing was posted in chat on join.

**The verdict.** One enum (`ClientVerdict`), computed in one place from the status snapshot, used by
`/lss status`, the status screen, the diagnostic export and the notice:

| Verdict | When |
| --- | --- |
| `WORKING` | negotiated, the server serves this player here, receiving is on, something can show it |
| `WORKING_DH` | terrain comes from this server's Distant Horizons |
| `WAITING` | still negotiating, or the Distant Horizons source has not settled |
| `LOCAL_WORLD` | the player's own world (singleplayer before Open to LAN) |
| `NO_SUPPORT` | the server never registered the handshake channel, and no Distant Horizons terrain either |
| `NO_ANSWER` | the channel exists but the server stayed silent (a proxy, a version skew, a saturated link) |
| `CLIENT_OUTDATED`, `SERVER_OUTDATED`, `VERSION_MISMATCH` | the server answered with a protocol this client does not speak: newer, older, or unknown |
| `SERVER_OFF` | the server answered "not for you here" |
| `NOTHING_TO_SHOW` | no LOD renderer and no map mod |
| `RENDERER_NOT_CONNECTED` | Voxy is installed and the bridge to it did not start (its internals changed) |
| `MAPS_BLOCKED` | a map mod is the only thing that could show the terrain, and the server asks clients not to write it into maps (status only) |
| `SOURCE_NOT_RUNNING` | the Distant Horizons source was running and stopped (its own lines say why) |
| `RECEIVING_OFF` | the player turned receiving off |
| `NOT_CONNECTED` | no server |

`/lss status` and the status screen open with it: "Working: receiving distant terrain from this
server." or "Not working: <reason>".

How the client knows:

- **No channel** is read from the loader every tick (`canSend` on Fabric, `hasChannel` on NeoForge)
  and reported after 100 ticks without it, because a plugin server registers its channels just
  after join. The claim is withdrawn the moment the channel appears. With no probe, or a probe that
  throws, the answer is "the channel exists": "no channel" is a claim about the server.
- **No answer** is the ladder's last rung plus one more rung of silence (30 s from the first
  announce with both compatibility rungs on). The ladder itself is unchanged.
- **Which side is older**: the status now carries the protocol number a rejected server answered
  with (it showed 0).
- **Distant Horizons states.** Where that source cannot run on this client (no LOD renderer, the
  Distant Horizons client mod installed) or found no service, the native answer decides, so a
  map-only client on a server without the mod reads `NO_SUPPORT`, not "add Voxy".

**The chat notice.** Grey, prefixed with the brand's short name in brackets so it does not read as
the server speaking. At most one per connection, only after the verdict has held still for 20 s
(longer than the Distant Horizons source's 15 s timers), and each kind a few times ever:

| Verdict | Cap | Text |
| --- | --- | --- |
| `NO_SUPPORT` | three times ever | "This server isn't sending distant terrain. It probably doesn't run <brand>. Nothing is wrong with your game." |
| `NOTHING_TO_SHOW` | once ever | "<brand> only downloads distant terrain. To see it, add the Voxy mod, or Xaero's World Map or JourneyMap for maps." |
| `RENDERER_NOT_CONNECTED` | (the same once) | "<brand> could not connect to your Voxy, so distant terrain can't be shown. Updating both mods usually fixes it." |
| `CLIENT_OUTDATED` | three times ever, shared by the three version answers | "Your <brand> is too old for this server, so you get no distant terrain. Update the mod to fix it." |
| `SERVER_OUTDATED` | (shared) | "This server's <brand> is older than yours, so you get no distant terrain. Only the server can update it." |
| `VERSION_MISMATCH` | (shared) | "This server's <brand> speaks a different version than yours, so you get no distant terrain. Update whichever is older." |
| `SERVER_OFF` | three times ever | "Distant terrain is switched off here by the server: for everyone, for this world, or for you. Nothing is wrong with your game." |
| everything else | never in chat | status only |

Every kind is capped, not only "no support": a player whose usual server has the mod switched off
or runs another version would otherwise read the same line on every join. The status always has
the verdict.

There is no setting for the notices: the caps make one unnecessary, and a new key in the main client
file would stop that file loading on 0.21. The caps are four counters in `notices.properties` beside
the client's terrain cache, not a history of servers. A file that cannot be read means "say
nothing", and a counted notice is spoken only after its count was saved, so a broken or read-only
directory cannot turn a capped notice into one repeated on every game start. The player's own
world and a LAN host get no notice.

**The server's half.** A player refused for lack of permission is told once per server start:
"This server gives distant terrain only to some players, and you aren't one of them." No
permission node is named (the gate needs both spellings, and a node means nothing to a player);
the nodes are in `/lsslod diag`. A served player whose permission is revoked is told too, whatever
they were told before. It is a system message with the English text as its fallback, so it
reaches old clients, and it is sent on both server cores. A 0.22 client on a 0.22 server that
refuses it for permission therefore reads the server's line at join and, up to three times ever,
its own less specific one 20 s later; telling the client the reason takes a flag in the session
answer and is left for 0.23.0 (§7).

**Strings.** Rewritten where this section touches them: "Reception: ON; consumer: none",
"Connection: awaiting negotiation", "Sharing preference not sent: no negotiated server channel.",
"Rebase and save". Every string has en_us, zh_cn and zh_tw and reads correctly under both brands
(the notices carry the full name, which the VSS build rewrites; the prefix is the brand's short
name). The hide-permission chat line keeps its 0.21.0 wording: its test pins the node and the
setting name, and it shipped a day ago.

## 2. Counters in diagnostics

- **Recovered errors** (built): `FaultCounters` counts failures the mod survives, by site, logs each
  site at most once a minute, and `/lsslod diag` ends with "Recovered errors: …" when any were
  counted. Diagnostics and exports only, never the player's status screen.
- **Protocol dialects** ([decision 0003](../decisions/0003-protocol-dialect-usage.md)): the tracker
  already totals sessions since start. A session is counted once, under the dialect it ended with
  (today a slow client's ladder counts 20, 19, 16, 20), with the uptime the totals cover
  (`ended=…/…/…/… in 3h05m` on the `Dialects:` line). In memory only: no file. Via-translated
  sessions are not tallied separately: a refused one never reaches the tracker.

## 3. Command names: moved to 0.23.0

The Voxy Server Side build answering to `/lss`, `/lsslod` and `lss.admin` as well as its own names
([decision 0005](../decisions/0005-command-roots.md)) is not in this release. It changes command
registration on four server platforms and the Paper build's text rewrite, and it is best shipped
with the settings work in 0.23.0, where the documentation it serves is rewritten anyway.

## 4. Far players are drawn to their full range by default

`far_players.extend_far_plane` defaults to on and takes effect while an LOD renderer is a consumer
([decision 0004](../decisions/0004-far-plane-default.md)). The extension is a grow-only latch: the
frame is vanilla until a far player is beyond the plane.

- **1.21.1** (28 % of players): the vanilla plane is 768 blocks at render distance 12 and the
  server sends far players to 2,048. This is where the default changes what players see.
- **26.x and 1.21.11**: the plane is already 2,048 by default; the change matters only when the
  server's ring is larger or the player lowered Cloud Distance.
- Existing players: off was the default and was never stored, so everyone moves to on. A sidecar
  that says `true` now repeats the default and is dropped at the next save. `false` is stored.
- The status line says how many far players the server sends (since 0.21.0). "How many are
  beyond the plane" was dropped: the extension's own diagnostics line already says whether it is
  extending, and the count would need a per-frame read on the status path.
- **Not in this release:** on 26.x far players fade out past about 900 blocks because of the
  game's atmospheric fog, which Voxy's default fog mode keeps. In October VoX decided far players
  keep vanilla fog and the tooltip says to turn the LOD mod's fog off. Exempting far players from
  fog while an LOD renderer is active would finish the job on 26.x; it reverses that decision, so
  it is put to VoX separately.

## 5. Beta releases

`release.yml` learns prerelease tags (`vX.Y.Z-beta.N`, with the usual `+mc<line>` suffix): Modrinth
version type `beta`, a GitHub prerelease, never Latest, not featured. The previous-tag lookup sorts
prereleases below their release and a stable release compares against the previous stable tag.
`gradle.properties` carries the prerelease version on the beta commit (the Sponge metadata test
requires it to equal the tag). `publish_vss.py` and `publish_curseforge.py` refuse prereleases.
1.21.1 carries its own `release.yml` and `release_check.py`; both are edited by hand there.

## 6. Tests and checks

- Unit tests for each rule, each proven by one deliberate break.
- Real-stack rows (Fabric 26.3 with Sodium, Voxy and Xaero; NeoForge 1.21.1): join a server
  without the mod, one with it off, one with it on; read the notice and the verdict from the
  client log and a screenshot. Run them on the VSS-brand jars too: 86 % of players use that build
  and it is the only one that exercises the brand rewrite.
- The Astra visual pass, recorded as run or as skipped with the reason.
- The beta soaks 72 hours on the test server before 0.22.0 is cut.

## 7. Not in this release

- **Settings tolerance** (0.23.0, own plan). Rule to build from: a file that is not YAML fails as
  today; an unknown key outside the protected groups is ignored with a warning; when a file has
  any unknown key, every protected key it does not declare takes its fail-closed value
  (`far_players.mode` off, hide holders, no map ingestion, require permission, x-ray masking on),
  and a key or section within two edits of a protected name fails that group closed even when
  declared; a wrong value takes the fail-closed value where one is at least as private as anything
  the operator could have written, and otherwise stops the feature; `generation.enabled` falls
  back to off; a reload still rejects wrong values; the operator sees a console block repeated
  after startup, a line to each admin on join, and "Reloaded with 1 problem"; unknown keys are
  preserved on save in the main file.
- **Command names** for the Voxy Server Side build (0.23.0, §3).
- **Why the server refused, told to the client** (0.23.0): one more bit in the session answer's
  flags (0.19 to 0.21 clients mask unknown bits) would let the status say "this server gives
  distant terrain only to some players" instead of "for everyone, for this world, or for you",
  and let the client stay silent where the server already spoke.
- **"Voxy is installed but not drawing"** (the graphics backend is not OpenGL) as its own
  verdict: the mod has no reliable signal for it today. It needs a read of the renderer's state
  per line. A bridge that failed to start is covered (`RENDERER_NOT_CONNECTED`).
- A generation distance cap: a key without a default changes nothing. If load proves to be a
  problem, the answer is a tick-time gate that delays generation, with the cap beside it.
- Protocol range negotiation, the client source/consumer bus, one server source for Paper, map
  facades, block light for lightless chunks, singleplayer without LAN.

## 8. Review fold (2026-11-13)

| Finding | Disposition |
| --- | --- |
| Ladder exhaustion is not "no LSS": the server stays silent on skew and Via mismatch, and a saturated link walks every rung | `NO_SUPPORT` means the handshake channel was never registered, read after the Distant Horizons timers; a silent channel is `NO_ANSWER`, never in chat, never remembered |
| "Once per server address, ever" keeps a history of servers and misfires behind proxies | lifetime caps (three notices ever for `NO_SUPPORT`), no address store |
| `notices.enabled` would break downgrades and is not needed | dropped |
| `enabled=false` also means "off in this dimension" | the text says "for everyone, for this world, or for you"; once per connection, not remembered |
| Voxy installed but not drawing reads as "working" | not built: no reliable signal today (§7). The Voxy advice is given on every loader |
| Naming a permission node to a player is wrong and reveals configuration | no node; once per server start; also on revocation |
| Ignoring a bad settings key turns far players on (`far_player: {mode: off}`) | the whole section moved to 0.23.0 with fail-closed rules for protected keys (§7) |
| A persisted dialect counter answers little; the tracker already totals sessions; `onHandshake` counts every rung | no file; count once at disconnect; Via tally and uptime added |
| Faults on the player's status screen would generate reports | diagnostics and exports only, labelled "Recovered errors" |
| `/vss` on an LSS server helps nobody | one direction only: the VSS build accepts the LSS names (0.23.0) |
| A Brigadier redirect alias skips the permission check and breaks the bare root | the tree is built once per name (0.23.0) |
| Paper's VSS rewrite would turn the alias into itself; `release_check` forbids the token | swap rewrite and the pair check changed together (0.23.0) |
| The far-plane premise was wrong for 26.x: its limit is fog, and 1.21.1 is where the plane cuts | §4 rewritten; decision 0004 corrected; the fog question goes to VoX |
| `isVoxyBridgeActive()` is a launch flag | the default takes effect while an LOD renderer is a consumer |
| A generation cap needs a new terminal answer and a client re-ask, and a key with no default does nothing | dropped |
| git sorts `-beta.N` above the release; contract tests pin the tag pipeline; CurseForge would upload a beta | §5 |
| Seven sections were too much for one release | settings, the generation cap and the command names removed |

## 9. Found while building

| Finding | What was done |
| --- | --- |
| `DORMANT` meant four things (own world, receiving off, another source selected, nothing announced), so "this is your own world" would have been said on servers | a `LOCAL` discovery state for the own world; the rest read `WAITING` until a fact settles |
| With the Distant Horizons source selected (the default) the native gate is "not asking", so a server without the mod would never be named | the channel fact is reported whether or not the client asked |
| A map-only client on a server without the mod read "add Voxy" (the Distant Horizons source needs it) | where that source cannot run, the native answer decides |
| "Once per connection" for "switched off here" and for a version mismatch repeats on every join to the same server | every kind has a lifetime cap |
| A caps file that cannot be written would repeat a capped notice on every game start | count first, speak second; unreadable means silent |
| A map-only client on a server that asks for no map writes was negotiated, enabled, and receiving nothing: it would have read "Working" | `MAPS_BLOCKED`, in the status only |
| A player whose Voxy the bridge could not hook into would be told to "add the Voxy mod" | `RENDERER_NOT_CONNECTED`: installed (a real version in the status) and no consumer |
| "Update whichever is older" leaves the player guessing | the status carries the server's protocol number; two texts |
| The server's line and the client's notice can both appear for one permission refusal | accepted for now, bounded by the caps; the fix is the reason flag (§7) |
