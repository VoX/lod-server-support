# LSS 0.24.0 release preparation

Prepared 2026-11-27 on the four shipping lines: 26.3, 1.21.1, 26.2 and 1.21.11. **Not tagged.**
The tags wait for the visual pass. 26.1 and 1.21.10 are frozen
([decision 0001](../decisions/0001-line-tiers.md)). Identities, counts and jar hashes are in the
[manifest](../implementation/2026-11-27-v0.24.0-release-preparation.json). Notes:
`v0.24.0-release-notes/` (one file per line).

## Scope

The code of [0.24.0-beta.1](2026-11-23-v0.24.0-beta.1-release-preparation.md)
([plan](2026-11-21-v0.24.0-plan.md)) under the stable version, plus:

- **#436**, merged after the beta: a `/lss fillmap stop` or a Fill Map press that waits for the
  client's cache to load reaches the saved record, and a stop in a session that downloads
  nothing says that nothing is running.
- **The stable review's fold of #436** (plan §11): a press after such a stop is the one saved,
  and a stop is honoured in every dialect (older-dialect sessions load the cache too).
- **A gametest fix:** `diskReadServesDoNotSeedTheDirtyContentFilter` asks again on a fresh
  service when its one disk read ran out of time, inside a budget of 2400 ticks
  ([flake catalog](../operations/test-flakes.md)). It was the first 26.3 gate's one red.
- **Notes and README** tightened after the review; no default changed.
- 26.2 and 1.21.11 receive the whole release as a port from main; 1.21.1 moves from the beta to
  the stable version.

So stable is not byte-for-byte the beta's code (decision 0002 says "same code"): the client-side
Fill Map record changed in about 30 lines, all of it pinned by tests through the real cache files.

measurement rig (plan §12).
