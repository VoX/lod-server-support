## The crash fix that skipped the soak

Found on 2026-11-13 while preparing 0.23.0: a real-stack run
(`20261113T212354Z-fabric-26.3-sodium-voxy-xaero`) ended with a server crash report,
`ConcurrentModificationException` in `ChunkGenerationService.tick`, one tick after the tool
kicked its player with 40 generations in flight.

- **Cause.** Fabric fires its server disconnect event from whichever comes first, netty's
  `channelInactive` or the server thread's own disconnect handling. The mod ran its whole
  cleanup in the event body, so on a network thread it changed the generation service's map
  while the server thread was iterating it. The handler dates from the first release; Fabric
  servers only (NeoForge and Paper clean up on the owning thread).
- **How often.** The server thread holds its iterator across each finished chunk's
  serialization, so the window is milliseconds in every tick that finishes a chunk. A
  disconnect the server issues (a kick or ban, a keep-alive timeout, the idle kick) is sent just
  before the mod's tick and closes on netty at once. Of the 13 earlier real-stack runs that
  kicked a player with generations in flight on a Fabric server, 1 crashed. Generation is on by
  default. No issue reports it.
- **Fix.** The event body reads the player's id and hands the cleanup to the server thread
  (`server.execute`). A stopped server runs that task on the calling thread; the cleanup then
  leaves the service to its own shutdown. A gametest fires the event from another thread and is
  red without the handoff; a contract test pins the wiring.
- **Why it is in 0.22.0 without a new beta.**
  [Decision 0002](../decisions/0002-beta-first-releases.md): "A crash or security fix may skip
  the soak. The release notes say that it did." They do. The first call was to leave it for
  0.23.0; the review of the fix showed the crash is not rare, and 0.22.0 will be the recommended
  build for weeks.
- **Not in it:** the Fabric client's disconnect cleanup has the same thread problem (rare
  glitches, no crash reported). That change is larger and goes through the 0.23.0 beta.
- **Owed:** the two frozen lines (26.1 and 1.21.10) get crash fixes
  ([decision 0001](../decisions/0001-line-tiers.md)) and have the same handler. Their fix needs
  the tag tooling to release a frozen line first, and follows 0.22.0.
