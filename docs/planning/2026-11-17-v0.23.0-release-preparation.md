## Scope

The code of [0.23.0-beta.1](2026-11-13-v0.23.0-beta.1-release-preparation.md), under the stable
version, plus:

- **Sponge: a session ends on `ServerSideConnectionEvent.Leave`**, not `Disconnect`
  ([plan](2026-11-13-v0.23.0-plan.md) §11). `Disconnect` also fires for a connection that never
  reached play, and from Sponge's login thread, so a refused second login of an account that was
  online ended the online player's session. `Leave` is posted on the server thread, from
  `removePlayerFromWorld`, only for players who reached the world. Pinned by
  `SpongeConnectionEndContractTest` (a revert to `Disconnect` and a dropped guard both go red).
  Sponge ships from main only, so only the 26.3 notes mention it. It did not soak: the test
  server is Fabric.
- **The real-stack tool** gains a SpongeVanilla 26.3 row and a `session_ended` check; every run
  now waits for the server to log the leave and takes one more diag.
- 26.2 and 1.21.11 receive the whole release as a port from main; 1.21.1 moves from the beta to
  the stable version.

Nothing else a player or an operator can observe changed after the beta.

## Visual pass

Passed on 2026-11-23, all 11 rows, on a visible `lss-test-26.3` window with VoX present
("astra go"), driven by Astra (Codex 0.171.0, `gpt-6.2-astra`) in 17 minutes: the settings
mistake on the client and on the server, the three "switched off" answers and the permission
reason turned off, Voxy switched off, the "Extend Draw Range" label at GUI scale 3, the
Disconnect button, a kick, quitting from inside a world, and five kicks while the map fills
(terrain back within 14 s each time). The maintainer read the results, six of the screenshots and
the client logs: the only ERROR lines are the planted settings mistake and one vanilla ping
during a planned server stop; no "disconnect cleanup" line, no crash report.

Two things about the pass itself:

- The permission row could not pass as first written. A plain Fabric server has no permissions
  mod, so with `service.require_permission: true` it logs that it serves everyone and refuses
  nobody; `deop` changes nothing. The disposable test server got LuckPerms (official build
  5.5.85) and the row denies `lss.use` on the default group.
- A first run that day started on Codex's configured default model and was stopped part-way when
  VoX asked for Astra 6.2. Codex was updated (0.162.1 did not know the model), and the pass
  above is the complete second run. The runbook now names the model on the command line.
