# LSS 0.22.0-beta.1 release preparation

Prepared 2026-11-13 on two lines, 26.3 and 1.21.1 ([decision 0002](../decisions/0002-beta-first-releases.md):
a beta on the two full-tier lines, then 0.22.0 on the four shipping lines after 72 hours on the
test server). 26.1 and 1.21.10 are frozen at 0.21.0 ([decision 0001](../decisions/0001-line-tiers.md)).
Identities, counts and jar hashes are in the
[manifest](../implementation/2026-11-13-v0.22.0-beta.1-release-preparation.json). Notes:
`v0.22.0-beta.1-release-notes/` (one file per line).

## Scope

[Plan](2026-11-13-v0.22.0-plan.md): two reviewers before implementation (§8), three after (§10).

- **Say why nothing is arriving** (§1): `/lss status`, the status screen and the export open with
  one verdict; a grey chat notice, at most once per connection and each kind three times ever.
- **Counters in diagnostics** (§2): "Recovered errors" by site; each ended session counted once
  under its protocol dialect.
- **Far players past the draw limit** (§4): `far_players.extend_far_plane` defaults to on and acts
  only while an LOD renderer is a consumer.
- **Beta releases** (§5): `release.yml` publishes `-alpha.N`, `-beta.N` and `-rc.N` tags as
  prereleases and refuses any other hyphenated tag; the manual NeoForge backfill, the VSS publisher
  and the CurseForge publisher refuse prereleases.
- **A truthful sharing message**: "Share My Position" saved while no server has received it says so.
- **Tooling**: the gate picks a JDK directory, newest by version.

Taken out in review: a line from the server to a player it refuses for lack of permission
(operators could not turn it off; plan §10). Not in it: settings tolerance, the VSS build answering
to the LSS command names, version skew explained in chat (all 0.23.0).

Each rule has a test that one deliberate break turns red: 17 for the first cut and 19 for the
review fold on main (one exposed a redundant guard, which was removed), 7 of them repeated on the
1.21.1 port.

## Real stacks (private displays, disposable local servers, no accounts)

`tools/realstack` (PR #401) on the gated jars: a real server and a production client with the
published mods players use. Eight runs, eight passes.

The scenario is the one the release exists for: a player on a server without the mod is told why,
once. On NeoForge it also proves the channel fact both ways (present with the mod, absent
without). The first VSS run was red for the tool's own reason: it asked the console for
`lsslod diag` and that build's command is `vsslod` (fixed in the tool; the server and client had
worked).

Not covered by a real run: "switched off here" (needs a server restart with the service off), a
version the server does not answer, a NeoForge client on a Paper or Fabric server.

## Visual pass

Skipped for the beta, with the reason: the Astra pass needs a visible desktop window for the 26.3
client and VoX present ("astra go"). What this release shows a player is text (a chat line and the
first line of the status), which the real-stack runs read from the client's own log. The pass is
owed before 0.22.0.
